# Security Policy

## Supported Versions

The latest release receives security fixes. Update before you report a problem that only affects an older release.

## Report a Vulnerability

Use [GitHub private vulnerability reporting](https://github.com/MaibornWolff/sandbox/security/advisories/new).

Do not open a public issue, pull request, or discussion. Include the affected version, impact, environment, and a minimal reproduction when possible.

We aim to acknowledge reports within five business days. We will coordinate a disclosure date after we confirm the issue and prepare a fix.

## Scope

Reports about isolation failures, permission bypasses, secret exposure, or network-policy bypasses are in scope. Reports about vulnerabilities in third-party tools inside a user-configured image should go to the relevant upstream project.

Read the [security model](README.md#security-model) before you report expected behavior as a vulnerability.

## Safe Harbor

We will not pursue legal action against researchers who act in good faith, avoid privacy violations and service disruption, and allow reasonable time for remediation. This policy does not authorize testing systems that you do not own or have permission to test.
